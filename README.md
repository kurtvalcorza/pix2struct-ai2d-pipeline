# Pix2Struct AI2D-base diagram question answering pipeline

DIMER inference wrapper for **Pix2Struct fine-tuned on AI2D** (`google/pix2struct-ai2d-base`), Google Research's 282M-parameter image-encoder/text-decoder that answers a multiple-choice question about a science diagram *from pixels* — the question and its numbered options are rendered as a text header above the diagram and the model generates the option text — pinned to an immutable Hugging Face revision and loaded only from a digest-verified local snapshot. The pipeline accepts one diagram image, one question and 2–6 options, decodes greedily under a caller-owned token budget, and returns the generated text plus the option it matches (or `None`) with a `truncated` flag; it returns no score and no location, and it renders the header with Pillow's bundled font so no font is fetched from the Hub at inference time.

## Upstream alignment

- Model: `google/pix2struct-ai2d-base`
- Revision: `0d6b2606efe05c77c1d0670647740802a9e68eef`

## Quick start

```python
from PIL import Image
from pix2struct_ai2d_pipeline import Pix2StructAI2DPipeline

pipe = Pix2StructAI2DPipeline.from_pretrained()        # stages + verifies weights/pix2struct-ai2d-base first
result = pipe.answer(Image.open("volcano.png"), "What does the label 15 represent?", ["lava", "core", "tunnel", "ash cloud"])
print(result["answer"], result["choice_index"], result["truncated"])   # generated text + matched option index (or None); no score
```

Install into a Python 3.12 environment that already holds the pinned dependencies with `pip install -e . --no-deps`; run `pytest -q -o addopts= tests` for the offline test suite (no weights needed). On a fresh clone the manifest is committed but the weights are not: `Pix2StructAI2DPipeline.from_pretrained(allow_download=True)` fetches exactly the missing manifest-listed files at the pinned revision, then verifies them.

## Weights layout

```
weights/pix2struct-ai2d-base/
  dimer-base-manifest.json   # modelId, revision, per-file bytes + SHA-256 (8 files)
  config.json                # Pix2StructForConditionalGeneration: 12-layer ViT encoder + 12-layer text decoder
  preprocessor_config.json   # is_vqa: true, max_patches 2048, 16x16 patches
  special_tokens_map.json  spiece.model  tokenizer.json  tokenizer_config.json
  model.safetensors          # git-ignored, 564,606,744 bytes (bfloat16 storage; upcast to float32 at load)
  README.md
```

`pytorch_model.bin` exists upstream and is deliberately not listed (pickle; DIMER does not accept `.bin`).

## Input ceilings and request parameters

`MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`; `MAX_QUESTION_CHARS = 256`; `MIN_OPTIONS = 2`, `MAX_OPTIONS = 6`, `MAX_OPTION_CHARS = 64` (distinct after normalisation); `MAX_NEW_TOKENS = 64`, `DEFAULT_MAX_NEW_TOKENS = 16`; `DECODING = "greedy"`; `MAX_PATCHES = 2048` (the processor's patch budget, documentation only). See `MODEL_CARD.md` for who owns the budget, the prompt format, the header-font substitution, the option-set sensitivity and the measured CPU timings.

## Tutorials

[![Open In Colab](https://colab.research.google.com/assets/colab-badge.svg)](https://colab.research.google.com/github/kurtvalcorza/pix2struct-ai2d-pipeline/blob/main/tutorials/pix2struct_ai2d_colab.ipynb)

`tutorials/pix2struct_ai2d_colab.ipynb` is declared `TASK-INFERENCE` / `GUIDED` under DIMER Notebook Specification 2.0 and is **standalone** (§4): generated by `tools/build_notebook.py`, it carries the pipeline module, model identity, manifest digests and runtime pins, so the exported notebook runs without this repository (parity enforced by `tests/test_notebook_parity.py`). Its default `Run all` path draws a 640×640 cartoon plant diagram with six numbered markers in code with ten authored multiple-choice questions (no download; six of them are recorded misses kept on purpose), surfaces the ceilings, exposes the caller-owned `max_new_tokens` as a form parameter, resolves the pinned model through the carried staging and verification path, validates the request through `validate_inputs` into an input manifest, answers through `Pix2StructAI2DPipeline.answer`, writes an `evaluation_report` whose `accuracy`, `unmatched_rate` and `chance` entries are sanity evidence only (`sample-sanity` against the authored labels, `not-measurable` without; no AI2D benchmark), and exports JSON, an answers CSV and an annotated PNG. BYOD (your own diagram and questions) is optional and gated off by default. See `tutorials/README.md` for the registry and `docs/release-verification.md` for the release gate.

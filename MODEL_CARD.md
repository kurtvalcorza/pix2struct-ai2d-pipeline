#### Description

`google/pix2struct-ai2d-base` is the Transformers-format release of the Pix2Struct *base* model fine-tuned on AI2D, from "Pix2Struct: Screenshot Parsing as Pretraining for Visual Language Understanding" (Lee et al., arXiv:2210.03347), converted from the T5X checkpoints by the Hugging Face team and pinned here to revision `0d6b2606efe05c77c1d0670647740802a9e68eef` (the Hub's `main` on 2026-09-14). The snapshot `config.json` declares `Pix2StructForConditionalGeneration`: a 12-layer ViT-style image encoder (hidden size 768, 12 heads, feed-forward width 2048, 16×16 patches with learned row/column position embeddings over a variable-resolution input of up to 4096 patch positions) and a 12-layer T5-style text decoder (hidden size 768, 12 heads of width 64, vocabulary 50,244, `max_length` 20) — 282M parameters stored in **bfloat16** in the 565 MB `model.safetensors` and upcast to float32 at load. The model was pretrained by parsing masked web-page screenshots into simplified HTML and fine-tuned on AI2D (Kembhavi et al., 2016: about 5,000 school-science diagrams with 15,000 multiple-choice questions, the diagram's text labels replaced by numbered markers). At inference the VQA processor (`Pix2StructImageProcessor`, `preprocessor_config.json`: `is_vqa` true, `max_patches` 2048) **renders the question and its numbered options as a text header above the diagram** (the pinned README's `<question> (1) <a> (2) <b> …` format, produced by `format_prompt`), scales the composite to fill at most 2048 patches while preserving aspect ratio, normalises it per image and flattens it into patch tokens; the decoder then generates the answer text, which `match_option` matches to the options by normalised exact match. Nothing is trained or adapted here. What this repository adds is packaging: `verify_snapshot` and `stage_missing_files` (manifest digest checking and fresh-clone staging), `Pix2StructAI2DPipeline.from_pretrained` (verified local loading with `trust_remote_code=False`, refusing a snapshot whose processor is not the VQA variant), `header_font_bytes` (Pillow's bundled Aileron Regular passed to the image processor so the upstream inference-time download of `ybelkada/fonts/Arial.TTF` never happens — a deliberate, documented departure from the upstream rendering font), `answer` (input validation, prompt formatting, greedy decoding under a caller-owned `max_new_tokens`, option matching, a `truncated` flag), `normalize_answer`, `format_prompt`, `match_option`, and the `validate_inputs` and `evaluation_report` stage helpers.

#### Intended Use and Limitations

The uses below are the ones the package was built to support; everything else is either out of scope (§Out-of-scope use cases) or prohibited (§Use cases).

###### Primary Intended Uses

The task is multiple-choice question answering over a diagram: input one diagram image (`PIL.Image.Image`, any mode, converted to RGB), one question (up to 256 characters), 2–6 distinct options (up to 64 characters each) and a token budget; output the generated option text, the index of the option it matches (or `None`), the number of tokens generated and whether the budget was exhausted. Envisioned applications are educational tooling that checks diagram comprehension questions, prototyping of diagram-reading assistants for textbooks and technical manuals, and screening large diagram collections for questions worth a human look — with every answer checked against the diagram by a person before it is graded, published or acted on. The pipeline is an inference component and a zero-configuration baseline for diagram QA, not a certified grader for any curriculum or diagram style.

###### Primary Intended Users

Intended users are machine-learning engineers, education-technology developers, and researchers integrating diagram question answering into research prototypes or in-house tooling. A user is expected to understand that the output is *generated text* — it carries no probability, no correctness signal and no location in the diagram, and the model answers every question, including unanswerable ones, with equal fluency — that the text is matched to the options by exact normalised equality and can match none of them (`choice_index` `None`), that the answer depends on the option set and not only on the diagram (the smoke run answered `root` to a label question whenever `root` was an option and `leaf` when it was removed), that the token budget is theirs to set, that the prompt is rendered into the image with a font this repository supplies (not the one used at fine-tuning time), that the model was fine-tuned on textbook science diagrams with numbered markers so cartoons, photographs, charts and non-English questions are distribution shifts, that greedy decoding is reproducible on a fixed device but GPU and CPU outputs need not match, and that accuracy can only be measured on labelled questions they supply. Users who need open-ended answers, evidence regions, diagram text transcripts or batch throughput are expected to know none of that is provided here.

###### Out-of-scope use cases

1. **Capability boundary:** no open-ended answering (generated text is matched to the supplied options; unmatched text is reported as `None`, not interpreted), no answer localisation or evidence region, no confidence, no abstention (the model cannot say "cannot tell"), no diagram text transcript, no multi-diagram or multi-page handling, no batching (each question is a full encoder pass), no sampling or beam search, and no arithmetic or multi-hop reasoning — AI2D answers are options read off the diagram's structure.
2. **Input boundary:** `answer` rejects non-PIL images (`TypeError`), sides below `MIN_IMAGE_SIDE = 16` px or above `MAX_IMAGE_SIDE = 4096` px, empty or non-string questions, questions longer than `MAX_QUESTION_CHARS = 256`, fewer than `MIN_OPTIONS = 2` or more than `MAX_OPTIONS = 6` options, empty, non-string, over-long (`MAX_OPTION_CHARS = 64`) or duplicate-after-normalisation options, and budgets outside `[1, MAX_NEW_TOKENS = 64]` (`ValueError`/`TypeError`). The diagram and the header share at most 2048 patches of 16×16 px, so a long prompt shrinks the diagram's share and markers only a few pixels tall at that scale are unlikely to be read. The bundled header font covers printable ASCII; a prompt with other characters renders with missing glyphs.
3. **Input boundary:** the fine-tuning data is AI2D — grade-school science diagrams (life cycles, food webs, anatomy, geology, astronomy) drawn in textbook style, with numbered markers and four options per question. Flat cartoons (the tutorial's plant), photographs, charts, flowcharts, engineering drawings, non-English prompts and questions whose answer is not an option fall outside what the upstream authors evaluated and what this repository measured; results on them are undefined, not merely degraded. An image that is not a diagram at all still produces text (see §Risks and harms).
4. **Decision boundary:** not for autonomous decisions that act on answers — automated grading, adaptive-learning placement, certification, or any assessment of a person — without a human comparing each answer with the diagram, and a locally measured accuracy on the deployment's own labelled diagram questions.

#### Factors

###### Groups

This pipeline is not human-centric by design: it answers a question about a diagram image and never classifies, identifies or scores people. The fine-tuning data (AI2D: diagrams scraped from Google image search for grade-school science topics, annotated by crowd workers) contains no evaluation groups in the demographic sense, and neither the upstream authors nor this repository audited it for anything of the kind. What does vary is the diagram population: AI2D is English-language, US-curriculum, textbook-style illustration, so diagrams in other languages and scripts, other curricula and drawing conventions, hand-drawn or photographed diagrams, and subjects outside grade-school science are the groups whose answer accuracy is unknown, not known to be equal. Where the tool is used to assess people — students answering diagram questions, candidates in a test — the operator is responsible for a fairness audit on their own question set, stratified by curriculum and diagram style, before any answer influences a decision about a person; the model's own answers on the tutorial cartoon (4/10, chance 0.25) show how far a drawing style can move it.

###### Instrumentation

The upstream pretraining "instrument" is a web renderer (screenshots of pages paired with their HTML) and the fine-tuning instrument is web-scraped textbook illustration at whatever resolution the source served, with numbered markers pasted over the original labels and the question rendered above each diagram in the Arial font the Pix2Struct preprocessing uses. Inference images arrive from whatever produced them — a PDF renderer at some DPI, a scanner, a phone camera, a drawing library — and resolution, skew, compression, marker size and drawing style all change the visual evidence; the 2048-patch budget fixes the encoder's input size regardless of the source, so a large diagram loses detail while a large blank margin costs patches. This repository renders the prompt with Pillow's bundled Aileron rather than Arial, a second instrument change whose effect was measured only on the synthetic diagram. The pipeline validates type, size, question and option shape only; it cannot detect a low-DPI render, a non-diagram image, or an unanswerable question. The synthetic tutorial diagram (flat Pillow shapes, white marker boxes, Pillow's bundled font) is itself a rendering instrument unlike any AI2D illustration, which is why its misses are recorded rather than treated as anomalies.

###### Environment

Operating environment: Python 3.12 with `torch==2.14.0`, `torchvision==0.29.0`, `torchaudio==2.11.0`, `transformers==4.57.6`, `safetensors==0.8.0`, `numpy==2.5.3`, `pillow==11.3.0`, float32 on CPU (the checkpoint's bfloat16 tensors are upcast at load); CUDA is used automatically when visible (float32) but was not exercised for this card. Measured on the reference machine with the GPU hidden (`CUDA_VISIBLE_DEVICES=-1`) and the Hub offline (`HF_HUB_OFFLINE=1`): load 5.22 s (verify of the 8-file, 565 MB snapshot included); one 640×640 drawn diagram, ten questions at the default budget, 2.07–2.40 s per question (2–3 tokens each); a 4096×4096 blank image 4.28 s — cost is dominated by the encoder pass over the 2048-patch input, which repeats for every question, and only weakly by the answer length. Data environment: the model assumes the image is a textbook-style science diagram with numbered markers and that the answer is one of the options; the synthetic tutorial diagram violates the first assumption on purpose (flat cartoon), which is where the recorded misses come from. Photographs, charts, non-English prompts and unanswerable questions violate it to degrees this repository did not measure, and the pipeline reports no signal when they do — nor when the image is not a diagram at all.

#### Metrics

###### Performance Measures

The pipeline reports no accuracy measure. The answer is generated text with no score, probability or correctness signal; `choice_index` is a normalised exact match of that text against the options (`None` when it matches none), and `new_tokens` and `truncated` describe the generation, not its quality. The repository ships the benchmark's own measure because it is what a caller would use to evaluate: **accuracy** — the matched option equals the labelled correct option, with an unmatched answer counted as wrong — alongside the **unmatched rate** and a **chance baseline** (the mean of 1/options over the questions). All need labelled multiple-choice questions on diagrams from the deployment domain that the caller must supply; the AI2D benchmark is not bundled. The public `evaluation_report(results, correct=None)` stage returns that report in machine-readable form: `accuracy`, `unmatched_rate`, the `chance` baseline and one per-question entry (prediction, matched index, correct index and option, correct flag) with the verdict `sample-sanity`, or the verdict `not-measurable` naming the labelled set that would be required when no labels are supplied. The upstream paper's AI2D test accuracy for the base model (upstream-reported; not restated here because the hosted card gives no number) is not reproduced or claimed by this pipeline.

###### Decision thresholds

No score threshold exists in the model: it generates tokens until end-of-sequence or the budget and nothing is filtered or abstained; the only "decision" is the exact-match rule in `match_option`, which is strict on purpose (no fuzzy, prefix or substring matching) so that a garbled answer such as `root root (2) root` is reported as `None` rather than guessed. The request parameter is the **token budget** `max_new_tokens`, default `DEFAULT_MAX_NEW_TOKENS = 16` (an option-sized budget chosen by this repository; the checkpoint's own `text_config.max_length` is 20, and the ten smoke answers needed 2–3 tokens) with ceiling `MAX_NEW_TOKENS = 64`. A budget that is too small is reported, not hidden: `truncated` is true whenever `new_tokens` reaches it (a budget of 1 flags the complete one-token answer `root` as truncated — the flag is conservative), and the caller should raise the budget and rerun. Decoding is greedy (`do_sample=False`) with no temperature, beams or repetition penalty. The option set is part of the request: the same question with different options yields a different answer, so a deployment owns the options it supplies as much as the budget, and decides how an answer is verified against the diagram before it is used.

###### Approaches to uncertainty and variability

This repository reports no central metric value and therefore no dispersion: the smoke run records timings, token counts and the answers to ten authored questions on one synthetic diagram, not accuracy. Run-to-run variability comes only from floating-point kernel selection across CPU builds and accelerators; there is no sampling and no seed to set, so a fixed input on fixed hardware is repeatable, but because decoding is autoregressive a single differing token changes the rest of the answer, and CPU and CUDA outputs need not match; the synthetic diagram's own bytes depend on the Pillow build's bundled font. On the drawn plant the model answered 4 of 10 questions correctly (`accuracy` 0.4 against a chance baseline of 0.25, `unmatched_rate` 0.0) — one observation on one flat cartoon, not an estimate: it answered `root` to the label questions 1–4 whenever `root` was among the options (correct only for label 4), `sun` for label 5 and `water` for label 6 (soil), `root` and `sun` correctly for the below-the-soil and light questions, and `leaf` and `root` for the stem and top-of-plant questions; with `root` removed from label 1's options it answered `leaf`, and with synonyms (`blossom`, `foliage`, `stalk`, `taproot`) it answered `blossom` — correctly — so the answer is a function of the option set. On a blank white image it produced `root root (2) root root (3) root root (4) root` (matching no option) and on uniform noise `leaf`, which is what an uncalibrated generator with no abstention looks like. A caller who needs an accuracy estimate must supply labelled questions and compute accuracy over many diagrams or bootstrap resamples themselves; a caller who needs a confidence per answer has none from this model.

#### Ethical considerations and biases

No external ethics board, red-team, or population-specific clearance reviewed this repository or, to our knowledge, the upstream checkpoint; nothing below should be read as implying one.

###### Data

The upstream paper describes pretraining on 80M masked web-page screenshots paired with simplified HTML (from the C4 corpus's URLs) and fine-tuning on AI2D, whose diagrams were collected from Google image search for grade-school science topics — copyrighted textbook illustrations whose reuse terms the dataset does not clear — and annotated by crowd workers; personal data is unlikely in science diagrams but web screenshots can contain it. Neither was audited here. This repository distributes code, tests, and documentation; it does not distribute the 564,606,744-byte `model.safetensors`, which is staged locally under `weights/pix2struct-ai2d-base/` and git-ignored, and it ships no sample diagrams — the tutorial diagram is drawn in code. The operator must audit the diagrams they submit for personal, proprietary, or otherwise restricted content; the pipeline performs no such check.

###### Human Life

This pipeline is not intended for decisions in health, safety, criminal justice, employment, credit, or housing, and it has not been validated or certified for any of them by this repository, the upstream authors, or any regulator. Foreseeable but unintended sensitive uses — auto-grading students' diagram questions, answering safety-critical questions about wiring, plumbing or medical diagrams, reading circuit or process diagrams to drive an action, screening technical drawings for compliance — would be admissible only with human comparison of every answer against the diagram (the model picks an option, or emits unmatched text, whether or not the question is answerable), a locally measured accuracy on the deployment's own labelled diagrams, a documented budget and option policy with `truncated` and `None` handling, and whatever regulatory clearance the domain requires.

###### Mitigations

- **Supply-chain integrity:** `MODEL_REVISION` is a 40-hex commit; `stage_missing_files` refuses a manifest whose `modelId`/`revision` differ from the package constants and fetches only manifest-listed files at that revision when `allow_download=True`; `verify_snapshot` then checks all 8 listed files' byte sizes and SHA-256 before any load; `from_pretrained` loads only from the verified directory with `local_files_only=True`, always passes `trust_remote_code=False`, refuses a snapshot whose image processor is not the VQA variant, and the smoke run loaded and answered with `HF_HUB_OFFLINE=1`. The upstream `pytorch_model.bin` (pickle) is neither listed nor loaded. **The inference-time font download the upstream processor performs (`ybelkada/fonts/Arial.TTF`, unpinned, unlisted) is replaced** by `header_font_bytes()` — Pillow's bundled Aileron Regular (CC0) — and the loader calls the image processor directly because `Pix2StructProcessor.__call__` drops the `font_bytes` keyword. A test flips one hex digit of a manifest digest and asserts the loader refuses; another asserts a foreign manifest is refused; the import-boundary tests assert that a missing or tampered snapshot is refused before `torch` or `transformers` is imported; another asserts the header font bytes are TrueType and stable.
- **Input integrity:** the public `validate_inputs(image, questions, *, max_new_tokens)` stage applies exactly the checks `answer` applies (both route through one shared private checker) and returns an input manifest recording the schema, the ceilings, the observed input, each checked question with its options and rendered prompt, the budget and the verdict; `validate_image` rejects non-PIL inputs and sides outside 16–4096 px; empty, non-string or over-long questions, malformed, too few, too many, empty, over-long or duplicate options, and out-of-range or boolean budgets are rejected; `answer` raises on a malformed runner result; `match_option` never guesses; `evaluation_report` rejects mismatched or invalid labels.
- **Reproducibility:** exact `==` pins in `pyproject.toml`; greedy decoding with no sampling; a fixed, bundled header font; a fixed prompt format; every result carries `model_id`, `model_revision`, the checked question and options, the rendered prompt, the budget, `new_tokens`, `truncated`, `choice_index`, the device and the dtype.
- **Refusals:** no batching, no download without the explicit flag, no Hub access at inference time, no sampling, no pickle deserialisation, no fuzzy option matching, no attempt to guess whether the diagram can answer the question.
- No statistical mitigation (class balancing, subsampling) applies: no training happens in this repository.

###### Risks and harms

- **Invented answers:** the model has no abstention — a blank image yielded `root root (2) root …` and noise yielded `leaf` in the smoke run — so an unanswerable question, a wrong image or a leading option set produces text, and often a matched option, with no signal; downstream consumers that trust `choice_index` (graders, databases, LLM pipelines) inherit the error silently.
- **Option-set dependence:** the answer changes when options are reordered, removed or replaced by synonyms (`root` → `leaf` → `blossom` in the smoke run for one question); a deployment that authors options carelessly authors the answers.
- **Plausible wrong options:** a wrong option is a fluent, short answer with the same shape as a right one; only labelled evaluation on the deployment's diagrams shows the rate, and the tutorial's 4/10 says nothing about it.
- **Automation bias:** an option matched exactly invites trust that generated text has not earned; the header-font substitution adds an untested variable.
- **Unmatched text:** a garbled answer is reported as `None`; a caller who treats `None` as "wrong" in a grader, or as "skip" in a pipeline, makes a policy choice the model cannot inform.
- **Truncation:** an answer longer than the budget is cut (reported via `truncated`); a caller who ignores the flag may match a partial option or nothing.
- **Bias amplification:** any diagram population AI2D under-represents (other languages, curricula, drawing styles, subjects) is reproduced as uneven accuracy, undetected because no per-family evaluation exists.
- **Resource use:** a 565 MB model and ~2.1–2.4 s per question on the reference CPU with a full encoder pass per question; a question-heavy workload scales linearly, and the CUDA path was not measured.

###### Use cases

Prohibited even where the model would work: using answers to grade, rank, place, certify or otherwise assess people without human review of every answer; answering questions about safety-critical diagrams (electrical, medical, structural, chemical) to drive actions; processing diagrams the operator has no right to process, including copyrighted textbook material outside its licence terms; deceptive uses that present generated answers as verified facts or as evidence; and any use that violates the upstream Apache-2.0 licence terms, the terms of the deployment that runs the pipeline, or the consent and data-protection obligations attached to the material processed. Autonomous high-consequence actions triggered by unreviewed answers are prohibited by the intended-use contract above.

## Input/output contract

- `Pix2StructAI2DPipeline.from_pretrained(device=None, weights_dir=None, allow_download=False)` — stages missing manifest files (only with `allow_download=True`), verifies digests, loads; `device` defaults to `cuda:0` when visible, else `cpu`; float32 on both.
- `answer(image, question, options, *, max_new_tokens=16) -> dict` with keys `answer` (stripped decoded text), `choice_index` (matched zero-based option or `None`), `question` (whitespace-collapsed), `options` (checked), `prompt` (`<question> (1) <a> (2) <b> …`), `image_size`, `new_tokens`, `truncated`, `generation` (`max_new_tokens`, `do_sample` false, `decoding` greedy), `device`, `dtype`, `source`, `model_id`, `model_revision`.
- `normalize_answer(text) -> str`; `format_prompt(question, options) -> str`; `match_option(answer, options) -> int | None`; `header_font_bytes() -> bytes`.
- Ceilings and constants: `MIN_IMAGE_SIDE = 16`, `MAX_IMAGE_SIDE = 4096`, `MAX_QUESTION_CHARS = 256`, `MIN_OPTIONS = 2`, `MAX_OPTIONS = 6`, `MAX_OPTION_CHARS = 64`, `MAX_NEW_TOKENS = 64`, `DEFAULT_MAX_NEW_TOKENS = 16`, `DECODING = "greedy"`, `MAX_PATCHES = 2048`, `INPUT_SCHEMA`.
- `validate_inputs(image, questions, *, max_new_tokens, names) -> dict` where `questions` holds `{question, options}` mappings; `evaluation_report(results, correct=None, *, sample_kind) -> dict` where `correct` holds one zero-based correct index per result; `verify_snapshot(path=None) -> dict`; `stage_missing_files(path=None, *, allow_download=False, downloader=None) -> list[str]`.

## Conformance notes

- **Standalone carrier (NOTEBOOK_SPEC 2.0 §4):** the primary path performs no clone, repository install, or repository import. Section 2 is `src/pix2struct_ai2d_pipeline/pipeline.py` verbatim (tagged `metadata.dimer.embedded_module`; the only rewrite makes the default weights directory working-directory-relative), Section 3 carries the model identity and the 8-file SHA-256 manifest inline and asserts they agree with the module before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the generating revision, the module's SHA-256, and the generator version.
- **Parity (PAR1–PAR3):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried module, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD8):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry; `from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files with `local_files_only=True` and `trust_remote_code=False` through `Pix2StructForConditionalGeneration`/`Pix2StructProcessor` (bfloat16 storage upcast to float32). The upstream `pytorch_model.bin` is not listed and not used. **The header font is supplied by the carried module** (`header_font_bytes`, Pillow's bundled Aileron) so the upstream processor's inference-time download of `ybelkada/fonts/Arial.TTF` never happens; the notebook's only external dependencies are the pinned PyPI distributions and the Hub at the model revision.
- **Role stages:** `validate_inputs` writes `outputs/pix2struct_ai2d_input_manifest.json` with the schema (header rendering, patch budget, option matching, decoding rule), the ceilings, the input's observed mode and size, each checked question with its options and the exact rendered prompt, the budget, the verdict, and one recorded rejection finding from the single-option probe; `evaluation_report` writes `outputs/pix2struct_ai2d_evaluation_report.json` — `sample-sanity` with `accuracy`, `unmatched_rate`, the `chance` baseline and one entry per question on the synthetic diagram; `not-measurable` on BYOD (with what labelled data would make the task measurable).
- The default sample is a deterministic 640×640 cartoon plant diagram drawn in code with six numbered markers in Pillow's bundled font (the AI2D convention: numbers on the diagram, words only in the options) — the same drawing the smoke run used; `accuracy` against labels you authored yourself is sanity evidence for the input contract, header rendering, forward pass, decoding and option matching, not an AI2D metric. **Six of the ten questions are recorded misses** (the smoke run answered `root` to nearly every label question whenever `root` was an option; 4/10 against chance 0.25); they stay in the scored set so the report shows what wrong and option-dependent answers look like. The image digest depends on the Pillow build's bundled font rendering and is printed, not asserted.
- Score semantics (UNC1–UNC4): the answer is generated text with no score, probability or correctness signal, matched to an option by exact normalised equality or reported as `null`; the notebook says so before the first answer and again in the interpretation section, states that the answer depends on the option set, and states that the model answers unanswerable questions (blank image → unmatched text in the smoke run). The token budget is a caller-owned request parameter exposed as a `# @param` value (default `DEFAULT_MAX_NEW_TOKENS = 16`) and passed explicitly on every `answer` call; `truncated` is surfaced and explained. The notebook performs no validation of its own — image, questions, options and budget are checked only by the pipeline's `validate_inputs`/`answer` path.
- Ceilings `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MAX_QUESTION_CHARS` (256), `MIN_OPTIONS` (2), `MAX_OPTIONS` (6), `MAX_OPTION_CHARS` (64), `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (16) and `DECODING` are printed before the model runs.
- CPU is documented as adequate (card-measured 5.2 s load, 2.1–2.4 s per question on the 640×640 diagram; 4.3 s on a 4096×4096 blank image); the notebook states that cost is per question and that GPU output need not match CPU output token-for-token.
- `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the
  clean-runtime execution requirement; a release review must confirm that a recorded clean run in
  `docs/release-verification.md` matches the notebook revision under review before the status is
  promoted to `Release-grade`.

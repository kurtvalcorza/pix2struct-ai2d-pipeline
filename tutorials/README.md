## What changed from the inference-only tutorial

The previous notebook (`TASK-INFERENCE`) answered ten authored questions on a drawn plant diagram and reported accuracy against labels you drew yourself as sample-sanity evidence, because no labelled diagram set was bundled. This notebook keeps that diagram and its inference contract as Section 5 and adds the adaptation contract around it: a real labelled corpus (one pinned shard of AI2D test questions, split by diagram), multiple-choice metrics and two non-neural baselines in the carried `metrics.py`, a bounded fine-tuning of the answer decoder, a per-category breakdown, the diagram re-answered after adaptation, and an artifact that reloads. The per-diagram `evaluation_report` helper is unchanged; `pipe.evaluate` is the corpus-level stage (`measured` / `measured-small-sample`). Whether the frozen model beats chance and whether the adapted model beats the frozen one are recorded as `frozen_beats_chance` and `adapted_beats_frozen`, not asserted, until a measured run is on file.

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 8-file snapshot manifest inline and asserts it against the module's constants before fetching, and `NOTEBOOK_SOURCE` records the repository, revision and module digests in the exports.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9, MOD12):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries a fresh clone lacks (the git-ignored `model.safetensors`), at the pinned revision; `verify_snapshot` re-hashes every entry before `torch` is imported; `Pix2StructAI2DPipeline.from_pretrained(weights_dir=WEIGHTS_DIR)` loads the verified files (`local_files_only=True`, `trust_remote_code=False`) and refuses a processor that is not the VQA variant; the header is rendered with Pillow's bundled font, so the Hub font the upstream processor would fetch is never downloaded. No cell outside the carried modules calls `huggingface_hub`, `transformers`, `pyarrow`, `safetensors` or `urllib`.
- **Data (DAT1–DAT9, ST6):** the default sample is one object in the Hub dataset repository `lmms-lab-encoder/ai2d` at the immutable revision `c83a9b9692933aff8349157c88a413df9d02c4e5` (`data/test-00000-of-00002.parquet`, 62,292,686 bytes), downloaded whole and refused unless its size and SHA-256 equal the pins in `samples.py`; `fetch_corpus` refuses to run at all while no SHA-256 pin is recorded (`tools/pin_corpus.py` records it from a verified download). Questions are grouped by diagram (content digest), a seeded subset of whole diagrams is allocated to test, validation and training until each reaches its question target, and `check_split_disjoint` asserts no shared diagram.
- **Stages (§4.1):** `fetch_corpus` + `read_corpus` + `build_sample_dataset` / `load_byod_dataset` + `split_dataset` (sample acquisition) → `validate_dataset` + `check_split_disjoint` + refusal probes (validation) → `validate_inputs` + `pipe.answer` with sanity checks + `evaluation_report` on the drawn diagram (inference contract) → `position_prior_baseline` + `longest_option_baseline` + `pipe.evaluate` on the frozen model with the per-category breakdown (baselines) → `pipe.adapt` (bounded fine-tuning) → `pipe.evaluate` on validation and test with the comparison (evaluation) → `pipe.answer` + `evaluation_report` on the drawn diagram again (inference) → `pipe.save_artifact` → `Pix2StructAI2DPipeline.from_artifact` with the parity assertion (export and reload).
- **Score semantics (UNC1–UNC4):** the answer is generated text with no score, probability or correctness signal, matched to an option by exact normalised equality or reported as `null`; accuracy counts an unmatched answer as wrong, so the unmatched rate is reported beside it; no acceptance threshold ships.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** chance, the position-prior and longest-option baselines and the frozen model are scored on the same test questions as the adapted model, overall and per category; every metric is labelled as one seeded split of one shard with no dispersion estimate.
- **Split integrity (SPL1–SPL8):** the split is seeded and diagram-disjoint; validation selects the epoch and the test split is used for nothing but the final evaluation; the notebook states that diagrams from few sources must be split by source.
- **Ceilings (VAL6):** `MIN_IMAGE_SIDE` (16), `MAX_IMAGE_SIDE` (4096), `MAX_PATCHES` (2048), `MAX_QUESTION_CHARS` (256), `MIN_OPTIONS` (2), `MAX_OPTIONS` (6), `MAX_OPTION_CHARS` (64), `MAX_NEW_TOKENS` (64), `DEFAULT_MAX_NEW_TOKENS` (16), `DECODING` and the record bounds (8..5,000) are stated in the Prerequisites and printed before the model runs; four dataset refusals and one input refusal are demonstrated.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, one zip is read member by member (names flattened, no `extractall`) and its records flow through the same validation, diagram-disjoint split, baselines, fine-tuning, evaluation, export and reload cells; the training split is written to `outputs/pix2struct_ai2d_train.jsonl` in the JSONL shape.
- Licence: the weights are Apache-2.0 and the notebook, README, card and `docs/WEIGHTS.md` say so; the Hub mirror of AI2D declares no licence, so the notebook states that AI2D's own terms must be checked before redistributing the diagrams or an adapter trained on them, and the export records the corpus repository, revision, file pin and that statement under `corpus`.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
